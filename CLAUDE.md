# PegasLogistic v1 — правила разработки

Проект живёт на проде с реальными сотрудниками. Язык всего — русский
(код-комментарии, коммиты, интерфейс, общение).

## Логика обновления инструкций (обязательно)

Инструкции сотрудников — `public/assets/guide.js` (массив `GUIDES`).
Любое изменение поведения интерфейса или процессов сопровождается
**в том же коммите**:

1. правкой соответствующего раздела `GUIDES` — тексты должны совпадать
   с реальными кнопками и порядком действий;
2. установкой поля `updated: 'ГГГГ-ММ-ДД'` (сегодняшняя дата) в каждом
   изменённом разделе — по этой дате у сотрудников загорается точка на
   кнопке «?» и бейдж «обновлено» на вкладке раздела, пока они не
   откроют инструкции.

Изменение без правки гайда допустимо только если поведение для
сотрудников не изменилось (рефакторинг, исправление данных).

## Рабочий цикл задачи

задача → код → `node --test` (все зелёные) → правка гайда + `updated` →
коммит (русское сообщение, трейлер Co-Authored-By Claude) → push в main →
деплой: `ssh root@91.144.178.239 'cd /opt/pegas-planner && git pull
--ff-only && docker compose up -d --build'` → проверить `git log -1`
на VPS (DNS github.com там падает — pull может молча не пройти) и статус
контейнера «Up N seconds» (up --build иногда не перезапускает) →
прод-проверка в браузере → обновить память проекта.

## Аудит сквозных связей (после каждой крупной фичи)

Завершая существенное изменение, прогнать аудит потребителей — грепом
по изменённым функциям/полям/статусам — и убедиться, что обновлены ВСЕ
зависимые места, а не только точка изменения:

1. **Информационные плашки и сводки**: KPI-плашки вкладок, бейджи,
   легенды, дашборд — показывают ли новые данные/статусы.
2. **Отчёты руководителя**: «📆 Отчёт дня», утренний авто-отчёт 07:00,
   «Показатели сотрудников», «Отклонения», табель — считают ли по
   актуальной логике (лучше через общую функцию, не дублями).
3. **Карточки**: карточка ТС, карточка сотрудника, карточка рейса —
   отражают ли новое состояние (пример пробела: подмена была в сетке,
   но не в карточке ТС — 1321c1b).
4. **Соседние роли**: видит ли изменение та роль, которой оно нужно
   (уведомления чата, задания, права tablo/manager — только чтение).
5. **Инструкции**: разделы GUIDES дополнены, `updated` = сегодня.
6. **Регламенты-документы** (docx): если изменение меняет порядок
   работы роли — отметить в ответе пользователю, что регламент
   требует переиздания.

Найденные пробелы закрывать сразу же, в той же сессии.
