# PegasLogistic Planner

Рабочая серверная версия прототипа `Диспетчерская_ТК_20.html`: планер рейсов, вход по учетной записи, ролевой доступ, администрирование, SQLite и контур обмена с 1С через OData.

## Быстрый запуск

Требуется Node.js 22.13+ (в проекте нет внешних npm-зависимостей).

```bash
cp .env.example .env
# задайте APP_SECRET и начальный пароль в .env
npm run db:init
npm start
```

Откройте `http://127.0.0.1:3000`. При запуске без `.env` создается пользователь `admin` с временным паролем `ChangeMe-2026!`. Пароль нужно сразу изменить в разделе «Настройки → Пользователи».

### Локальный запуск без домена

Для локального режима нужны только Node.js 22.13+ и одна команда:

```bash
LOCAL_ONLY=true bash ./deploy/deploy-to-vps.sh
```

Приложение откроется на `http://127.0.0.1:3000`, будет доступно только с текущего компьютера и не потребует DNS, Nginx или TLS-сертификата. Скрипт автоматически создаст отдельную локальную БД в `data/local/` и секреты в `.secrets/`, выведет начальный пароль администратора. Для другого порта добавьте, например, `LOCAL_PORT=8080`.

Данные находятся в `data/planner.db`. Для резервной копии используйте штатный SQLite backup:

```bash
mkdir -p data/backups
sqlite3 data/planner.db ".backup 'data/backups/planner-$(date +%F).db'"
```

## Что перенесено из HTML ТК 20

- десять геозон и их цвета;
- расшифровка геозон по городам/регионам и координаты для карты;
- фактический состав из 127 ТС, 1 651 рейса за июль 2026 и клиентская аналитика;
- расстояния и ставки по направлениям;
- полная экономика: НДС 22%/7% для ИП, дорожные, водитель, рефустановка, лизинг и накладные;
- статусы рейсов, причины отклонений и горизонт планирования;
- температурные режимы, кузова и шесть этапов заявки;
- интервалы ремонта, отсутствия водителя, пересменки и вывода ТС;
- расчет маржинального дохода/операционной прибыли, отчётные периоды и контроль пересечений более шести часов;
- роли логиста, ресурса, диспетчера, продаж, бухгалтерии и руководителя.

Теперь параметры хранятся в БД и редактируются администратором, а не в JavaScript.

Исходные массивы ТК 20 зафиксированы в `src/tk20-data.json`. Повторно извлечь их из новой копии HTML можно командой:

```bash
node scripts/extract-tk20-data.mjs /path/to/Диспетчерская_ТК_20.html
```

Seed версионирован ключом `tk20_seed_version`, поэтому перезапуск не дублирует рейсы. Перед применением к существующей локальной БД создана резервная копия `data/backups/planner-before-tk20.db`.

## Обмен с 1С

Настройка выполняется в «Настройки → Интеграция 1С»:

1. Опубликуйте стандартный OData-интерфейс нужной информационной базы по HTTPS.
2. Создайте отдельного пользователя 1С с минимальными правами на нужные справочники и документы.
3. Укажите URL вида `https://host/base/odata/standard.odata`, логин и пароль.
4. Для каждой сущности задайте реальное имя набора OData и карту полей.
5. Включите правила загрузки и выполните тестовый ручной запуск.

Пароль 1С шифруется AES-256-GCM с ключом, производным от `APP_SECRET`, и не возвращается в браузер. Загрузка обходит страницы `@odata.nextLink`, но не разрешает переход на другой хост.

Дополнительно реализован версионированный JSON-контракт из ТК 20:

- `POST /api/admin/integration/import/1c` — идемпотентный импорт рейсов; города автоматически преобразуются в геозоны;
- `POST /api/admin/integration/import/telematics` — фактический пробег, статус и время выгрузки;
- `GET /api/admin/integration/export?kind=plan|period|archive|clients` — выгрузка для 1С/BI;
- `GET /api/reports?from=YYYY-MM-DD&to=YYYY-MM-DD` — серверный экономический отчёт;
- `PUT /api/revenue-plans/YYYY-MM-01` и `POST /api/periods/YYYY-MM-01/close` — план выручки и закрытие периода.

Импорт из 1С использует внешний ключ `1c:<id>` и при повторной передаче обновляет существующий рейс. Телематика ищет запись по внутреннему или внешнему ID. Настройки её URL и токена находятся в «Настройки → Интеграции», токен хранится зашифрованным.

### Механизм обратной записи

Локальные изменения сначала транзакционно сохраняются в SQLite, затем попадают в таблицу `outbox`.

```text
Планер → SQLite → outbox → одобрение администратора → OData 1С → аудит
```

По умолчанию включен ручной режим и сама отправка отключена. Рекомендуемый ввод в эксплуатацию:

1. Добавить в объекты 1С реквизит `IntegrationKey` с уникальным индексом.
2. Добавить `idempotencyKey: "IntegrationKey"` в карту полей и проверять ключ до создания документа — это исключает дубли при повторе запроса.
3. Для существующих объектов хранить `Ref_Key` и `ETag`; обновлять через `PATCH`, конфликты версии отправлять на ручное разрешение.
4. Проверить сценарии create/update/пометка на удаление в копии базы 1С. Физический `DELETE` сервис не выполняет.
5. Включить отправку одобренных записей, оставить ручное подтверждение.
6. Только после приемочных испытаний рассматривать автоматическую политику.

Не рекомендуется делать синхронную запись в 1С прямо из HTTP-запроса пользователя: недоступность 1С не должна блокировать работу диспетчерской.

## Деплой на VPS / Proxmox LXC

Установка рассчитана на чистый Debian 12/13, в том числе в контейнере Proxmox LXC. Приложение и служба обмена запускаются в read-only Docker-контейнерах без Linux capabilities, с лимитами ресурсов и корректным PID 1; порт приложения доступен только на `127.0.0.1:3000` за Nginx, а внешний доступ ограничен списком подсетей из настроек администратора.

### Деплой одной командой (интерактивный мастер)

На чистом VPS/LXC выполните **от root**. Установщик `install.sh` сам поставит git, склонирует репозиторий (или обновит уже существующий каталог) и запустит мастер — команду можно запускать повторно:

```bash
apt-get update && apt-get install -y ca-certificates curl && curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/Tuma58/planner_pegas/main/deploy/install.sh | bash
```

Тот же запуск с рабочей станции (флаг `-t` даёт мастеру интерактивный терминал):

```bash
ssh -t root@192.168.10.50 "apt-get update && apt-get install -y ca-certificates curl && curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/Tuma58/planner_pegas/main/deploy/install.sh | bash"
```

Установщик идемпотентен: если `/opt/pegas-planner` уже существует и это тот же репозиторий, он обновляется fast-forward, а не вызывает ошибку. Каталог и ветку можно переопределить переменными `APP_DIR` и `REPO_BRANCH`.

Мастер пошагово спрашивает и проверяет параметры, показывает сводку по разделам (режим, сеть и подсети, сертификаты, учётные данные, безопасность, каталог/бэкапы) и запускает установку только после подтверждения. По завершении выводит URL, логин `admin` и пароль (также сохраняются на VPS в `/root/pegas-planner-initial-credentials.txt`, права `0600`). В мастере настраиваются:

- режим: `lan` (локальный TLS без внешнего домена) или `public` (домен + Let's Encrypt);
- репозиторий, ветка и доступ public/private (read-only deploy key);
- сеть: `LAN_HOST`/`LAN_CIDR` либо домен и email; SSH-порт;
- учётные данные администратора — пароль генерируется или вводится вручную (скрытый ввод, ≥12 символов);
- каталог приложения, расписание и срок хранения бэкапов;
- защита: nginx rate-limit и параметры Fail2ban.

Предпросмотр без установки (`DRY_RUN=1` печатает итоговую сводку и выходит):

```bash
DRY_RUN=1 DEPLOY_MODE=lan LAN_HOST=192.168.10.50 LAN_CIDR=192.168.10.0/24 bash /opt/pegas-planner/deploy/interactive-deploy.sh
```

Мастер не переспрашивает переменные, уже заданные в окружении, поэтому интерактивный ввод и автоматизация свободно комбинируются. Повторный запуск установщика безопасен (каталог обновляется, а не пересоздаётся); для штатного обновления уже работающей установки используйте `pegas-planner-update` (см. ниже) — она делает бэкап, health-check и откат при ошибке.

### Неинтерактивные однострочники (переменные окружения)

LAN-режим из публичного репозитория — команда с рабочей станции ставит на чистый VPS только `ca-certificates` и `curl`, остальное делает bootstrap:

```bash
ssh root@192.168.10.50 "apt-get update && apt-get install -y ca-certificates curl && curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/Tuma58/planner_pegas/main/deploy/deploy-public-lan.sh | env LAN_HOST=192.168.10.50 LAN_CIDR=192.168.10.0/24 bash"
```

LAN-режим из приватного репозитория — с рабочей станции, через read-only deploy key:

```bash
LAN_ONLY=true VPS_HOST=192.168.10.50 LAN_HOST=192.168.10.50 LAN_CIDR=192.168.10.0/24 REPO_URL=git@github.com:ORG/PRIVATE_REPOSITORY.git REPO_BRANCH=main DEPLOY_KEY="$HOME/.ssh/pegas-vps/deploy_key" KNOWN_HOSTS_FILE="$HOME/.ssh/pegas-vps/git_known_hosts" bash ./deploy/deploy-to-vps.sh
```

`LAN_CIDR` ограничивает SSH в UFW. Веб-доступ при первом запуске **открыт со всех подсетей** (`0.0.0.0/0,::/0`), чтобы администратор гарантированно вошёл; после первого входа веб-подсети ограничиваются в «Настройки → Сеть и доступ» без повторного деплоя (текущий адрес администратора нельзя удалить из списка — защита от самоблокировки). Стартовый список можно переопределить переменной `INITIAL_ALLOWED_SUBNETS`. Дополнительно можно передать `SSH_PORT`, `LAN_TLS`, `REPO_URL`, `REPO_BRANCH`. Для входа на VPS SSH-ключ должен быть заранее настроен, а host key VPS — проверен в локальном `known_hosts`.

После деплоя приложение откроется на `https://LAN_HOST`. Сертификат `/etc/pegas-planner/lan-tls.crt` установите в доверенные на рабочих ПК (пошагово для Windows/macOS/Linux — в docs). `LAN_TLS=false` отключает TLS и не рекомендуется — логин и пароль пойдут по HTTP.

`LOCAL_ONLY=true` и `LAN_ONLY=true` — разные режимы: первый запускает Node.js на текущем компьютере, второй ставит production-контур на удалённый VPS.

### Особенности Proxmox LXC

Перед сборкой bootstrap выполняет отдельный Docker runtime preflight. Если Docker внутри несовместимого LXC блокируется внешним AppArmor-профилем (`net.ipv4.ip_unprivileged_port_start`), установка останавливается с инструкцией **для хоста Proxmox**: обновить `lxc-pve` до `6.0.5-2` или новее, включить для CT `nesting=1,keyctl=1` и перезапустить контейнер. Скрипт намеренно не отключает AppArmor и не откатывает `runc`. Установка идемпотентна — после исправления хоста повторите ту же команду. Если на Proxmox без подписки `apt update` возвращает `401 Unauthorized`, отключите Enterprise/Ceph Enterprise репозитории через `Node → Updates → Repositories`, оставив `pve-no-subscription` текущего выпуска.

Контейнеры получают корректный PID 1 (`init: true`) и лимиты ресурсов, безопасные для небольшого LXC: `planner` — 512 МБ / 1.0 CPU, `sync-worker` — 256 МБ / 0.5 CPU. Значения переопределяются в `.env` каталога приложения: `PLANNER_MEM_LIMIT`, `PLANNER_CPU_LIMIT`, `WORKER_MEM_LIMIT`, `WORKER_CPU_LIMIT` (Node учитывает cgroup-лимит памяти сам). Готовность проверяется встроенным Docker healthcheck, а не HTTP-запросом с хоста, поэтому служебный адрес Docker bridge не нужно добавлять в пользовательский allowlist. Приложение штатно завершается по `SIGTERM`, закрывая HTTP-сервер и SQLite, что делает `docker stop` и обновления чистыми.

Bootstrap ставит: Docker Engine и Compose plugin, Git, OpenSSH server/client, Nginx, UFW, Fail2ban, `util-linux` (`flock`), SQLite CLI, OpenSSL, curl, CA-сертификаты, unattended security updates (для режима `public` — ещё Certbot).

Параметры, вынесенные в окружение/мастер (дефолты повторяют прежнее поведение): каталог `APP_DIR` и ветка `REPO_BRANCH`; пароль администратора `ADMIN_PASSWORD` (если не задан — генерируется); расписание и срок хранения бэкапов `BACKUP_ONCALENDAR` (systemd OnCalendar) и `BACKUP_RETENTION_DAYS`; nginx `RATE_LIMIT_RATE`/`RATE_LIMIT_BURST`; Fail2ban `F2B_MAXRETRY`/`F2B_FINDTIME`/`F2B_BANTIME`. Расписание бэкапа применяется через systemd drop-in override (`/etc/systemd/system/pegas-planner-backup.timer.d/override.conf`), поэтому переустановка базового юнита при обновлении его не затирает.

Новая установка при первом запуске открывает веб-доступ со всех подсетей (`INITIAL_ALLOWED_SUBNETS`, по умолчанию `0.0.0.0/0,::/0`), чтобы исключить самоблокировку администратора. Сразу после первого входа задайте фактические CIDR в «Настройки → Сеть и доступ». Это значение влияет только на инициализацию БД: при повторных деплоях и обновлениях пользовательский список подсетей не перезаписывается.

Полная пошаговая инструкция (сертификаты Windows/macOS/Linux, первый вход, приватный репозиторий, обновления) — в [docs/DEPLOY_LAN_VPS.md](docs/DEPLOY_LAN_VPS.md).

## Деплой на VPS с публичным доменом

Тот же результат даёт интерактивный мастер в режиме `public` (спросит домен и email для Let's Encrypt). Ниже — неинтерактивный путь через переменные окружения.

Bootstrap рассчитан на чистый Debian 12/13 с публичным доменом. Он устанавливает Docker из официального репозитория, Nginx, Let's Encrypt, UFW, Fail2ban, unattended-upgrades, SQLite CLI и Git. Приложение и worker запускаются в read-only контейнерах без Linux capabilities, а порт приложения доступен только через `127.0.0.1`.

Перед запуском:

1. Создайте `A`/`AAAA` запись домена на IP VPS.
2. Создайте для приватного Git-репозитория отдельный read-only deploy key.
3. Сохраните приватную часть ключа без passphrase локально, например `/path/to/pegas_deploy_key`.
4. Создайте отдельный `known_hosts` для Git-хоста и обязательно сравните fingerprint с опубликованным провайдером значением. Не используйте непроверенный результат `ssh-keyscan`.
5. Убедитесь, что SSH host key самого VPS уже проверен и записан в ваш локальный `known_hosts`.

Однострочная команда первоначального деплоя, выполняется из корня локального репозитория:

```bash
VPS_HOST=203.0.113.10 DOMAIN=planner.example.ru ADMIN_EMAIL=admin@example.ru REPO_URL=git@github.com:company/private-planner.git REPO_BRANCH=main DEPLOY_KEY=/path/to/pegas_deploy_key KNOWN_HOSTS_FILE=/path/to/git_known_hosts bash ./deploy/deploy-to-vps.sh
```

После завершения начальные реквизиты администратора выводятся в терминал и сохраняются на VPS в `/root/pegas-planner-initial-credentials.txt` с правами `0600`. Пароль нужно сразу сменить через интерфейс.

Bootstrap:

- разрешает firewall только для SSH, HTTP и HTTPS;
- отключает парольный SSH-вход, только если уже найден рабочий `authorized_keys`;
- ограничивает попытки входа в приложение и SSH;
- получает и автоматически продлевает TLS-сертификат;
- хранит `APP_SECRET` и начальный пароль вне Git в `.secrets/`;
- настраивает ежедневную SQLite-копию и хранение копий за 14 дней;
- использует проверенный host key и read-only ключ для приватного Git.

Если SSH работает не на порту 22, добавьте `SSH_PORT=2222`. Для входа не под `root` задайте `VPS_USER=deploy`; у пользователя должен быть passwordless `sudo` на время bootstrap.

### Обновление из приватного Git-репозитория

Однострочная команда update-deploy:

```bash
ssh root@203.0.113.10 /usr/local/sbin/pegas-planner-update
```

Скрипт получает настроенную ветку через сохраненный deploy key, запрещает non-fast-forward обновление, делает SQLite backup, пересобирает контейнеры и проверяет `/api/health`. При ошибке сборки, запуска или health-check код и контейнеры автоматически возвращаются к предыдущему commit; резервная копия БД остается в `/opt/pegas-planner/data/backups/`.

Полезные команды на VPS:

```bash
cd /opt/pegas-planner
docker compose ps
docker compose logs --tail=200 planner
docker compose logs --tail=200 sync-worker
sudo /usr/local/sbin/pegas-planner-backup          # разовый бэкап
systemctl status pegas-planner-backup.timer        # расписание бэкапа
systemctl list-timers pegas-planner-backup.timer   # ближайший запуск
```

Расписание бэкапа задано в `/etc/systemd/system/pegas-planner-backup.timer.d/override.conf` (`OnCalendar`), срок хранения — в `/etc/pegas-planner/deploy.env` (`BACKUP_RETENTION_DAYS`). После правки выполните `systemctl daemon-reload`.

Для нескольких экземпляров API необходимо заменить SQLite на PostgreSQL либо оставить ровно один writer.

Локальные копии на VPS не заменяют внешнее резервное хранилище. Настройте выгрузку каталога `data/backups/` и файлов `.secrets/` в зашифрованное off-site хранилище; без `APP_SECRET` восстановить сохраненный пароль подключения к 1С невозможно.

После настройки адреса 1С дополнительно ограничьте исходящий сетевой доступ worker до DNS/NTP, Git/Docker registries для обновлений и конкретного OData-хоста 1С. Bootstrap не может сделать это автоматически, поскольку адрес 1С при первом деплое неизвестен.

## Структура

```text
public/                 страницы входа, планера и настроек
src/server.mjs          HTTP API, сессии, RBAC и статика
src/db.mjs              схема SQLite, начальные справочники, аудит/outbox
src/planner-service.mjs контракты 1С/телематики и серверная экономика
src/odata.mjs           загрузка и отправка OData
src/tk20-data.json      версионированные исходные данные HTML ТК 20
```
