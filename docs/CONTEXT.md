Живой контекст: что это за система, как устроена и что происходит сейчас.
Обновляется минимум каждым пятым коммитом (правило в CLAUDE.md).
Секретов здесь нет и быть не должно: токены/пароли живут в настройках
приложения и на сервере.

Обновлено: 2026-09-12, вторая половина дня (коммит 475). Изменения
ревизии: карта уже на своём тайл-сервере; сборщик одометров получил

выгрузок чист — активных рейсов с завышенными сроками 0.

## Что это

TMS логистической компании «ПегасЛогистик»: планирование и контроль
рейсов рефрижераторного парка (~128 сцепок), конвейер заявок
продажи → логист → диспетчер → 1С, контроль на линии по данным
GPS/CAN (Пилот), экономика рейсов и самонастраивающиеся нормативы.
Прод живой, на нём работают сотрудники. Язык всего — русский.

## Архитектура

- Node.js ≥22, ES-модули, без npm-зависимостей; БД — node:sqlite
  (DatabaseSync), файл data/planner.db.
- Один сервер `src/server.mjs` (API + статика + фоновые сторожа),
  фронт — ванильный JS в `public/assets/*.js`, вкладки по ролям.
- Прод: Proxmox LXC (Debian), Docker Compose, приложение слушает :3000,
  nginx (443, TLS Let's Encrypt) проксирует; вход сотрудников изнутри
  сети — https://100.100.10.77, снаружи — https://planner.pegasavto.ru.
- Тайл-сервер карты — СВОЙ: /opt/tiles (russia.mbtiles из OSM-экстракта,
  tileserver-gl на 127.0.0.1:8081, nginx `/tiles/` с кэшем 30 дн).
- Telegram: оба бота (сотрудники, водители) живут в приложении; входящие
  вебхуки `/api/telegram/webhook/{staff|driver}` через 443; исходящие —
  api.telegram.org, при блокировке — релей (app_meta telegram_api_host,
  воркер в tools/telegram-relay-worker.js).
- Мониторинг: Pilot-GPS (blade.pilot-gps.com), позиции/датчики/одометры;
  лимит 8 rps, X-Node обязателен.

## Концепция живых нормативов (обязательная рамка)

Полный текст — CLAUDE.md. Кратко: никаких зашитых бизнес-констант;
пороги — из настроек (цели руководителя) или выучены из фактов с
клампом здравого смысла и формулой-фолбэком; каждый контур отчитывается
о дрейфе; автоматика рекомендует — человек решает; эффект меряется
данными Пилота. Реестр процессов — кнопка «🧠 Живые нормативы» у
руководителя (/api/self-tuning): коэффициент дорог, медианы плеч
(км и часы), ворота П/В, честный одометр, сегменты A/B/C/D, переменная
себестоимость, порог подгона, доверие автоназначению, норма ремзоны,
две ночные санации.

## Ключевые защиты данных (сентябрь 2026)

- Километры: 3 слоя (коридор чтения прямая×1,05…×1,65; эксклюзивные
  дни + кламп на записи; санация раздутых планов).
- Транзит: 3 слоя (коридор дорог км/80…км/22+8; кламп ворот 0,5–8 ч;
  санация — только сжатие, не раньше окна клиента и плановых точек).
- Факт рейса: лестница CAN-одометр → GPS-трек → эксклюзивные календарные
  дни → «не измерено» (вне обучения и инвентаризации).
- Местоположение: истина — конструкция (последняя выгрузка/перегон),
  GPS — сверка; расхождения ловит инвентаризация («Мониторинг молчит»,
  «GPS расходится с конструкцией»).
- Температура рефа: каждый отсчёт датчика несёт свою свежесть; старше
  3 ч — «датчик молчит», без тревог по протухшему.
