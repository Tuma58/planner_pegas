# Внутренний помощник PegasLogistic — концепция

Идея руководителя (02.11.2026): помощник, который копит базу знаний на
реальной работе и постепенно начинает в ней участвовать — «самообучалки
следующего уровня»: предупреждает сотрудника, когда тот ошибается, по
предыдущему опыту; подсказывает положительный опыт; постоянно помогает
оптимизироваться.

Документ — дорожная карта. Каждая ступень включается отдельным решением
руководителя и опирается на предыдущую.

## Принципы (те же, что у живых нормативов)

1. Помощник НЕ запрещает — подсказывает, с причиной и ссылкой на опыт.
   Решение всегда за человеком.
2. Каждая подсказка оценивается («полезно/нет») — бесполезные правила
   глохнут сами: это самообучение второго уровня.
3. Знания курируются: статьи пишет руководитель, сырьё копит система.
4. Эффект каждой ступени меряется данными (правило проекта «160 млн»).

## Ступень 0 — уже работает (фундамент, 09–11.2026)

Планер уже «предупреждает по опыту», точечно:
- живые нормативы: км/часы/скорости из фактов, клампы здравого смысла;
- сторожа: щит дублей заявок и водителей, залипшие одометры,
  недостижимые окна, геокод-карантин, окно клиента (вариант А);
- ночная автопроверка с докладом; еженедельные дрейфы нормативов.

Их слабость: каждый сторож — ручная работа разработчика. Следующие
ступени делают накопление знаний и подсказок системным.

## Ступень 1 — копилка знаний (ГОТОВО, 02.11.2026)

- `kb_articles` — статьи «вопрос → ответ», пишет руководитель/админ;
  источник — закрытые заявки HELP DESK (кнопка «📚 В статью») и ручные.
- Комната «❓ Справка» в чате: поиск по статьям (словоформы, лёгкий
  стемминг, public/assets/kb.js) и по инструкциям «?» (GUIDES).
- Оценки «👍 помогло / 👎 нет» на каждой статье: плохие статьи видны.
- `kb_misses` — вопросы без ответа: карта дыр базы, видна руководителю
  («🕳 Без ответа») и утреннему разбору в 7:00.

Метрика ступени: доля поисков с ответом; число статей; оценки.

## Ступень 2 — подсказки в момент работы (ЗАПУЩЕНА 02.11.2026)

Помощник смотрит на действие сотрудника и, если накопленный опыт знает
лучше, говорит об этом ПРЯМО В ФОРМЕ — до ошибки, а не после.

Фундамент готов (02.11): реестр правил `HINT_RULES` (src/assistant.mjs),
журнал показов/оценок `assistant_hints` (троттлинг «раз в сутки на
человека по контексту»), оценка 👍/👎 на каждой подсказке, дрейф — строка
«Подсказки помощника» в «🧠 Живых нормативах».

Правила:

- ✅ **«Ворота клиента»** (02.11, первое правило): продажи выбирают
  заказчика в форме заявки → если честная медиана «прибыл → выгружен»
  за 28 дн (методика «Дорогих ворот», от 3 рейсов; клампованные
  gate_facts НЕ годятся — урок калибровки 02.11) ≥ 1,5 цели
  gateTargetHours — подсказка «машина у этого клиента стоит N ч при
  цели M — закладывайте простой в ставку»; договорные исключены.
  Метрика эффекта: доля заявок таких клиентов со ставкой выше средней
  по направлению; договорные простои у «тяжёлых» клиентов.
- ✅ **«Выравнивание наката»** (02.11, второе правило): в подборе ТС
  выбрана сцепка с накатом ≥ цели dailyKmTarget, а среди кандидатов
  есть «голодная» (≤70% цели — порог зелёного бейджа) → первый клик по
  «Назначить» показывает подсказку с обеими машинами, повторный —
  назначает (мягкий щит, как у дублей заявок). Логика на фронте
  (runRateHint в sales.js, под тестом), троттлинг и оценки — сервер
  (/api/assistant/check + /vote). Метрика эффекта: разброс наката по
  парку (медиана/размах в «🎯 Подбор ТС» пн 08:00).

Следующие кандидаты (данные уже есть, нужен только вывод):
- Диспетчер ставит срок короче выученной физики плеча → предупреждение
  с выученным временем (транзит-клампы уже есть — добавить голос).
- Статья базы знаний всплывает по контексту: раздел статьи = вкладка,
  на которой сотрудник ошибается повторно.

Механика (реализована): правила добавляются по одному, каждое — с
метрикой эффекта (опоздания, простои, разброс наката). Никаких
всплывающих ковров: не больше одной подсказки на действие, повторно не
чаще раза в день на человека; правило с перевесом 👎 отключается
решением руководителя.

## Ступень 3 — ИИ-слой (по решению руководителя, когда наполнится база)

- Нейросеть (API) отвечает в «❓ Справке» своими словами по статьям,
  гайдам и контексту роли; при пустой базе бессмысленна — потому третья.
- Еженедельный «разбор ошибок недели» автоматом (как вестник, но внутрь
  процесса): что чаще всего исправляли, где теряли время, что улучшить.
- Цена вопроса: ключ API, рубли в день на офис; зависимость от внешнего
  сервиса — включается осознанным решением.

Критерий запуска: ≥30–50 живых статей и устойчивый поток вопросов из
«❓ Справки»; решение руководителя по бюджету.

## Что НЕ делаем

- Не заводим отдельную систему (всё живёт в планере и чате).
- Не даём помощнику право менять данные — только подсказывать.
- Не включаем ИИ-слой до наполнения базы и явного «делаем».
