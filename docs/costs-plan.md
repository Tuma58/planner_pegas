# План блока «Учёт затрат»

Дата: 03.11.2026. Заказ руководителя: «Нам необходимо реализовать учёт
затрат».

## Зачем

Сегодня в планере живут только **нормативные** затраты — Настройки →
Калькуляция (себестоимость ₽/км, водитель ₽/сутки, лизинг и накладные
₽/машино-день). На них стоят отчёты маржи, сегменты клиентов A/B/C/D и
переменная себестоимость `variableCostPerKm()`. **Фактических** затрат в
системе нет нигде: ремзона хранит работы и часы без сумм, выручка
считается каноном `tripNet`, а расходная сторона — рукой заданным
нормативом 55 ₽/км.

Цель блока: рядом с выручкой появляется факт затрат →
- настоящая прибыль периода (выручка − факт, а не выручка − норматив);
- живая себестоимость ₽/км, выученная из факта, с дрейфом против
  настройки калькуляции (концепция живых нормативов: настройка — цель,
  факт — проверка).

## Устройство (целевая модель)

**Таблица `expenses`** — одна запись = один расход:
- `spent_on` (день), `category` (из справочника), `amount` (₽, как в
  документе), `vat` (включён ли НДС — для приведения к без-НДС канону),
- привязки, все необязательные: `vehicle_id`, `driver_id`, `trip_id`,
- `supplier` (кому платили), `doc_ref` (номер документа/чека), `note`,
- `source` (`manual` | `import`), `created_by`, `created_at`.

**Справочник `expense_categories`** (посев меткой, CRUD у admin,
`active` вместо удаления — как склады LTL): топливо · ремонт и запчасти
· шины · мойка · стоянка · платные дороги и Платон · штрафы · зарплата
водителей · лизинг/амортизация · страхование · налоги · накладные ·
прочее. Каждая категория знает свой характер: `variable` (ложится на
км) или `fixed` (ложится на машино-дни) — это нужно Э4.

Разрезы отчёта: период × категория × машина. Деньги в отчётах — без
НДС (канон money.mjs), ввод — как в документе с флагом НДС.

## Этапы

### Э1 — Журнал затрат (фундамент)
- `expenses` + `expense_categories` с посевом; индекс (spent_on,
  category).
- API: список за период с фильтрами (категория, машина), добавление,
  правка, удаление своей записи (admin — любой); аудит каждого действия.
- Вкладка «Затраты» (видна `reports:read` и тем, кто вносит): форма
  ввода (день, категория, сумма, НДС, машина/водитель — по желанию,
  поставщик, документ, заметка), таблица периода, итоги по категориям и
  по машинам, единый пикер периода.
- Щит ввода: открытая форма переживает поллинг (чек-лист input-shield).
- Гайд: новый раздел «Затраты» + `updated`.

### Э2 — Импорт из файлов (по образцу сверки 1С)
- Кнопка «Импорт» на вкладке: xlsx/csv разбирается в браузере
  (xlsx-lite.js), колонки сопоставляются с полями, предпросмотр, затем
  пакетная вставка.
- Дедуп по отпечатку записи (день+сумма+категория+машина+документ):
  повторная загрузка того же файла не плодит дублей.
- Первые форматы — по тому, что реально есть у компании (решение № 1
  ниже): выгрузка 1С по статьям затрат и/или отчёт топливного
  процессинга по картам.

### Э3 — Затраты в отчётности
- «Отчёт периода» и «⚡ Сводка периода»: строка «Затраты (факт)» по
  категориям рядом с нормативными, настоящая прибыль = выручка − факт;
  пока категория пуста — честная пометка «не вносится», без подмены
  норматива фактом втихую.
- Карточка ТС: затраты борта за период, факт ₽/км (на канон пробега из
  журнала одометров).
- Покрытие: доля категорий, по которым факт вносится, — видна в отчёте
  (мера зрелости учёта).

### Э4 — Живой норматив себестоимости
- Фактическая переменная ₽/км парка = сумма variable-категорий /
  пробег периода (канон одометров); клампованная медиана по месяцам.
- Дрейф против `costPerKm` настройки — строка в «📐 Нормативы недели»
  и подсказка «обновите калькуляцию» при расхождении (как уже сделано
  для суточного пробега).
- Сегменты клиентов и маржа продолжают считаться через
  `variableCostPerKm()` — настройку правит руководитель по подсказке
  (автоматика рекомендует, человек решает).

## Решения (03.11.2026)

1. **Источник факта — решение руководителя:** выгрузки Excel и API из
   личных кабинетов поставщиков и клиентов. Э1+Э2 (журнал + импорт
   Excel/CSV) реализованы в тот же день; API-коннекторы — следующий
   этап, ждёт списка кабинетов и доступов (какие поставщики: топливный
   процессинг, Платон/Автодор, лизинг…).
2. **Кто вносит** (по умолчанию, возражений не было): бухгалтерия
   (роль accountant), руководитель, админ — право `expenses:write`.
3. **Привязка**: машина+день; поле trip_id в схеме есть — привязка к
   рейсу подключается позже без миграции.
4. **Зарплата и лизинг**: пока нормативами калькуляции; фактом — по
   отдельному решению.

## Касания существующего (аудит при реализации)

- money.mjs — не трогаем, выручка как есть; без-НДС приведение затрат —
  тем же `vatRate` калькуляции.
- Отчёты: planner-service.mjs (отчёт периода), briefReportData (сводка
  и PDF-колода), dailyOpsText, вестник — строка затрат добавляется в Э3.
- Ремзона: суммы ремонтов НЕ дублируем в двух местах — в Э2+
  обсуждается либо поле стоимости в заказ-наряде с автозаписью в
  журнал, либо ввод только в журнале с привязкой к машине.
- Права: permissions.mjs — новое право `expenses:write` (чтение — под
  `reports:read`).
