# Телефония: интеграция с Облачной АТС Билайн

Статус: **адаптер реализован** (`src/beeline-telephony.mjs`) — журнал звонков
опрашивается раз в минуту, пропущенные входящие поднимают карточку; события в
реальном времени (Xsi-Events) включаются публичным адресом в настройках.
Осталось: включить на проде и проверить подписку Xsi-Events (см. «Что дальше»).

## Что это

Облачная АТС Билайн (https://cloudpbx.beeline.ru) — провайдер виртуальной АТС.
Справка по API в личном кабинете — SPA-приложение
(https://cloudpbx.beeline.ru/new/#/features/api-money, раздел «API», вкладка
«Подключенные»): текст грузится скриптом после входа, поэтому «сырой» текст
раздела доступен только из кабинета. Ниже — выверенное по официальному порталу
API и подтверждённым интеграциям описание.

## Подключение услуги «Интеграция по API»

1. Войти в кабинет https://cloudpbx.beeline.ru/new/#/login под администратором.
2. **Настройки → API** (в части инструкций — «Услуги → Интеграция по API»).
3. Включить переключатель «Интеграция по API». Услуга **платная** — тариф
   изменится.
4. Нажать **«Создать (новый) токен»**, ввести имя (например, `PegasPlanner`),
   скопировать значение токена и сохранить.

Токен выглядит как UUID, пример: `8c0711c0-b11b-11fd-b111-111a111d18e1`.
Токен даёт доступ к данным АТС — хранить как пароль, в git не публиковать.

## Учётные данные API

- **Базовый URL:** `https://cloudpbx.beeline.ru/apis/portal`
- **Аутентификация:** заголовок `X-MPBX-API-AUTH-TOKEN: <токен>` на каждом
  запросе.
- Контрольная проверка: запрос портала без токена отвечает HTTP 403 с телом
  `{"errorCode":"AuthTokenNotFoundInRequest"}` — значит, токен обязателен.

## Что умеет API (два механизма)

1. **REST — история звонков (CDR) и записи разговоров.** Чтение с постраничным
   смещением (`offset`). Записи подтягиваются через несколько минут после
   завершения звонка и только для сотрудников, у которых включена услуга
   **«Запись разговоров»** (включается отдельно, на каждого).
2. **Xsi-Events (BroadWorks Xsi-Events) — события звонков в реальном времени.**
   Наше приложение регистрирует публичный HTTPS callback-URL, Билайн шлёт на
   него состояния звонка (начался / ответ / завершён). Подписка имеет срок
   действия — её нужно **продлевать** (автопродление делает наша сторона).

Важно: по изученной справке API работает **на чтение** — не размещает и не
управляет звонками. Исходящий click-to-call делается через SIP-софтфон
(отдельная настройка оборудования в кабинете), а не через этот REST-токен.

## Сопоставление сотрудников

Сотрудник Билайна сопоставляется с нашим сотрудником **по мобильному номеру
(11 цифр)**. Номер должен быть заполнен в справочнике и уникален. Совпадает с
нашим правилом «последние 10 цифр» (`phoneDigits` в `src/telephony.mjs`).

## Где хранится токен в нашем проекте

- Файл **`.secrets/beeline_ats_token`** (права 0600, каталог `.secrets/` в
  `.gitignore`) — сюда вставляется токен из кабинета. В git он не попадает
  (как `APP_SECRET` и `ADMIN_PASSWORD`).
- Читается в `src/config.mjs` через `secret('BEELINE_ATS_TOKEN', '')`:
  сначала env `BEELINE_ATS_TOKEN_FILE`, затем `BEELINE_ATS_TOKEN`, иначе
  пусто (телефония Билайна не подключена).
- Локальный запуск (`deploy/local-start.sh`) экспортирует
  `BEELINE_ATS_TOKEN_FILE="$project_root/.secrets/beeline_ats_token"`.

## Как это ложится на текущую инфраструктуру телефонии

У нас уже есть (коммит `8d5191a`): таблица `call_events`, вебхук
`POST /api/telephony/webhook`, определение звонящего `identifyCaller`,
карточка звонка `public/assets/call-card.js`, вопросы водителей с нормативом
10 минут.

Не путать токены:

- **Билайн-токен** (`X-MPBX-API-AUTH-TOKEN`) — им **наше** приложение
  аутентифицируется, когда ходит в Билайн (опрос CDR, подписка Xsi-Events).
- **Токен в «Настройки → Телефония»** (`X-Telephony-Token`) — это ДРУГОЙ,
  «наш» токен, которым АТС подписывает события, приходящие **на наш** вебхук.

## Подтверждённые endpoint'ы портала (проверены токеном)

Базовый URL `https://cloudpbx.beeline.ru/apis/portal`, заголовок
`X-MPBX-API-AUTH-TOKEN`.

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/statistics?page=N&pageSize=M` | журнал звонков (M от 10 до 100), новые сверху: `startDate` (мс), `direction` INBOUND/OUTBOUND, `status` MISSED/RECIEVED/PLACED, `duration` (мс), `abonent` (наш сотрудник: `userId`, `phone` = FMC-мобильный, `extension`, `department`). **Номера второй стороны нет** — `phone` равен мобильному нашего сотрудника |
| GET | `/abonents` | справочник сотрудников АТС (33 записи: `userId`, `phone`, `lastName`, `extension`) |
| GET | `/records` | записи разговоров (с `fileSize` и номером второй стороны), первые 100, старые сверху |
| PUT | `/subscription` | подписка Xsi-Events: тело `{"pattern","expires","subscriptionType":"BASIC_CALL","url"}`, ответ `{"subscriptionId","expires"}`; `pattern` = добавочный/номер сотрудника |
| GET | `/subscription?subscriptionId=` | состояние подписки |
| DELETE | `/subscription?subscriptionId=` | отмена подписки |

## Как реализован адаптер

`src/beeline-telephony.mjs` + сторож в `src/server.mjs`:

1. **Журнал звонков** — раз в минуту опрос `/statistics?page=1&pageSize=100`,
   дедупликация по внешнему ключу (`provider=beeline` + хэш события), запись в
   `call_events` с колонками `status`, `duration_ms`, `employee_phone`.
   `target_user_id` — наш сотрудник по FMC-мобильному `abonent.phone`.
   Запись помечается разобранной (`handled_at`): она не поднимает карточку,
   потому что номера звонящего статистика не несёт.
2. **Xsi-Events real-time** — при заданном в настройках «Публичный адрес»
   создаются/продлеваются подписки `BASIC_CALL` на **всех** сотрудников АТС
   (`/abonents`). События приходят XML'ом на `POST /api/telephony/beeline/events`,
   разбираются `parseXsiEvent` (callId, направление, номер звонящего) и заводят
   событие в момент звонка: входящий номер опознаётся `identifyCaller` и
   карточка поднимается ещё на вызове.

Ограничения: у `statistics` нет своего id — ключ дедупликации вычисляется из
содержимого; номер звонящего даёт ТОЛЬКО Xsi-Events, а он требует публичный
HTTPS-адрес, поэтому реальная доставка проверяется на проде.

## Что дальше

1. **Деплой на прод** и проверка: токен уже в `.secrets/beeline_ats_token`
   (на проде — тот же файл в каталоге приложения, заполнить там же).
2. В «Настройки → Телефония» включить «Телефония подключена», задать
   «Публичный адрес» (`https://planner.pegasavto.ru`) и «Номер слежения»
   (общий добавочный/номер приёма звонков) — после этого заработает
   Xsi-Events; проверить, что подписка создалась (лог «билайн: подписка…»).
3. Сверить сопоставление `abonents` ↔ наши сотрудники по телефонам: у кого
   телефоны не совпадают, входящий не привяжется к сотруднику.
4. Отдельно (не в этом этапе): исходящие click-to-call через SIP-софтфон и
   журнал звонков с записями разговоров (`/records`).
