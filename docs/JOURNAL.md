# Журнал изменений PegasLogistic v1

Каждое изменение проекта — строкой: дата, суть, хэш коммита.
Новые записи сверху. Ведётся с 12.09.2026 (правило в CLAUDE.md);
более ранняя история — в git log и памяти ассистента.

## 2026-09-15

- Ресурс: лента водителей в сетке — фамилия в ячейках на период
  закрепления (период главнее постоянного); после пересменки без
  назначенного следующего водителя — пустые ячейки с красной штриховкой
  «⚠ нет водителя». Закрепление упрощено: клик по ленте открывает диалог
  с заполненными сцепкой и датами, фокус сразу в поиске фамилии.

- GPS-автофакт выгрузки: нижняя граница поиска стоянки — выезд с погрузки
  ТЕКУЩЕГО рейса (кейс т935ав58 №3403: челнок на одну точку — визит
  прошлого рейса в 36-часовом окне закрыл новый рейс до его фактической
  выгрузки, машина ложно ушла в «свободные» у логиста). Данные №3403
  возвращены «в пути» до 16.09 07:00.

- Отчёт «🏭 Эксплуатация (планер)»: каскад КТГ/КВЛ/КИП из данных планера
  за произвольный период, без 1С; недели, сценарии к плану, клиенты,
  Печать/PDF (/api/park-report). Принят ЕДИНЫЙ канон КИП: на линии =
  «на линию»→выгрузка (+перегоны); под грузом = убытие с погрузки→
  ПРИБЫТИЕ на выгрузку; стоянка у клиента — потеря КИП.

## 2026-09-14

- Должностные инструкции (решение руководителя): docx-пакет Диспетчер/
  Логист/Продажи с таймингами из измеряемых нормативов (Ресурс и
  Механик — после доработки блоков). Цифровое ознакомление: таблица
  guide_acks, кнопка «✍ Подтвердить ознакомление» в инструкциях
  (приравнено к подписи, новая редакция запрашивает заново),
  руководителю — счётчик и список неознакомившихся.

- Пробег прицепа (фундамент ТОиР): /api/trailer-mileage — сумма пробегов
  тягачей по интервалам сцепки из журнала trailer_moves (перецепляли
  несколько раз — куски суммируются; без истории — честная пометка).
  Делёж звеньев получил фолбэк «по координатам перецепки» (прямая через
  погрузка→передача→выгрузка × коэффициент дорог). Перецепы дня внесены
  в журнал задним числом (время оценочное).

- Экономика перецепа: звенья рейса (trip_segments) — замена ТС на идущем
  рейсе автоматически закрывает плечо прежнего тягача (координаты
  передачи, CAN-одометры) и открывает новое; ночной collectSegmentEconomy
  делит выручку по честным км плеч (Пилот за интервал звена, фолбэк —
  длительность). Звенья в карточке рейса; отчёты перейдут на звенья
  отдельным этапом. АН 8377 58 → Паллет 33 (решение руководителя),
  П41 = 11 прицепов и 11 сцепок — норма сошлась.

- Тип ТС — от прицепа (правило руководителя): справочник trailers
  (самонаполняющийся из сцепок, дубли типов → пусто), тип тягача
  подтягивается при перецепке (карточка ТС, «🔗 Перецепка») и сторожем
  runTrailerTypeSync ежечасно; написание прицепов канонизируется при
  записи. Данные: оформлены 3 перецепа дня (АО6844→р274ун, АО5643→т944ав,
  АН8377→т046ав) и закрыты 4 старых дубля по решениям руководителя
  (АК6247→р208со, АМ6633→р901ар, АМ6455→с869рх, АН3471→т487ве,
  АО2401→р147мт) — дублей прицепов 0.

- Подготовка выхода: вернулась плашка «Ранее заказ внесён в 1С на прежнее
  ТС — внесите изменения» с кнопкой «✓ 1С обновлено». Пропала для
  основного пути замены (переназначение на том же рейсе): долг needs_1c
  показывался только в «Контроле на линии».

- Корректировка заказа: поле срока выгрузки называлось «Погрузка по» —
  диспетчеры считали, что выгрузка не редактируется (каскад на рейс при
  этом работал). Переименовано в «Выгрузка до (доставить к)» с подсказкой;
  та же подпись в форме заявки продаж и в списке правок для продаж.

- Ремзона: отдельный блок (уточнение концепции руководителем) — вкладка
  «Ремзона», заказ-наряды repair_orders (очередь → в работе → готов →
  выдан, одометр из CAN, механик, плановый выход) и работы repair_jobs
  (название/запчасти/часы). Блок АВТОНОМЕН: на подбор/гант/диспозиции не
  влияет до этапа интеграции; API /api/repairs*.

- Миграция users: CHECK ролей расширен значением mechanic (пересоздание
  таблицы по её же схеме с выключенными FK на время танца) — без неё
  вставка механика падала по constraint.

- Ремзона, этап 1 (старт блока, решение руководителя): роль «Механик»
  (mechanic: planner:read + fleet:write, первый — Тарасов Евгений);
  заезд в ремонт требует причину из классификатора (ТО/плановый/поломка
  на линии/ДТП/шины/документы/прочее) — в форме диспозиции, у кисти
  ресурса (селектор) и во внештатке «поломка» (автопричина); одометр
  борта на момент заезда пишется сам из CAN-датчика (odometer_km) —
  основа счётчика ТО этапа 2.

- Прогноз месяца пересмотрен (решение руководителя): факт прошедших дней
  + каждый оставшийся день по медиане выгрузок того же дня недели за
  5 недель (кламп ×0,5…×1,5 к среднему темпу), не меньше назначенного
  на день. Строка «🧮 Честно» переименована в «💼 Уже в кармане» с
  подписью «назначено до …» — читалась как заниженный прогноз.

## 2026-09-12

- Дашборд: строка «⚡ потенциал дня» у Сегодня/Завтра (план по назначенным
  + внесённые заявки без ТС). Продажи: яркий баннер «Выручка дня /
  ⛔ ДОБРАТЬ N» над плашками (пульсирует, пока план дня не закрыт).

- Ревизия v2: floor санации держат только точки, поставленные человеком
  (updated_by заполнен — возвраты, ручные правки); автосозданные точки
  наследовали старый транзит, душили санацию (сжато 0 из 18) и теперь
  подтягиваются вслед за новым концом рейса.

- Ревизия транзита по парку (команда руководителя): распределение
  план/формула по 138 активным — 73 в ±15%, 14 длиннее в окно клиента
  (законно), 18 хвостов старых медиан → режим sanitizeInflatedTransit
  (revision): разовое сжатие до честного расчёта с выигрышем от 2 ч,
  метка transit_revision_2026_09_12.

- Транзит: дорога плеча училась от отметки «на линию» — вбирала подгон,
  очередь и погрузку (Аустрина→Пермская: 28,3 ч при честных 15,8, ворота
  погрузки считались дважды). Теперь интервал «убытие с погрузки →
  прибытие на выгрузку», фолбэк «на линию».
- Километры плеча: порог 20 ч и эксклюзивные дни оставлены только
  календарному фолбэку — рейсы с честным одометром идут в медиану без
  них (было 3 образца при 19 одометрах).

- Сборщик честного одометра: очередь застревала на первых 120 безнадёжных
  кандидатах (Пилот не отдаёт данные за интервал; за сутки +1 рейс) —
  метка gps_km_tried_at, пробованные откладываются на 2 суток, дорога
  достаётся несканированным (~412 в очереди).
- Документация: созданы docs/CONTEXT.md (живой контекст) и этот журнал;
  правило «каждый 5-й коммит — ревизия документации» в CLAUDE.md.
- Карта переведена на собственный тайл-сервер `/tiles/` (tileserver-gl +
  russia.mbtiles 9,9 ГБ из OSM-экстракта; nginx-кэш 30 дн) после
  блокировки tile.openstreetmap.org — 3985299.
- Служба маршрута мака: маршрут 100.100.10.0/24 живёт только при
  активном офисном VPN, шлюз 192.168.89.170 — 1822295, aeea29f.
- Telegram: исходящие Bot API заблокированы провайдерами с ~08.09;
  добавлен релей через app_meta telegram_api_host + воркер
  tools/telegram-relay-worker.js — 739c4ef (ждёт воркер руководителя).
