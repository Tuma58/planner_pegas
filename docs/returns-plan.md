# Блок «Внештатки и возвраты» — план этапов

Заявка Базуева из HELP DESK (02.11.2026, ТЗ вложением; «мешает каждый
день»). План на утверждение руководителем — код пишется только после
«делаем» по этапу.

## Суть

Рейсы с внештатными ситуациями трёх типов — **акт на выгрузке**,
**возврат продукции** (кол-во паллет/коробок), **опоздание на П/В** —
собираются в отдельную вкладку; возвраты живут цепочкой статусов до
закрытия, с привязкой к складам LTL. Сегодня возвраты продукции не
живут в системе нигде — а это деньги, паллеты на чужих складах и
обещания клиентам, которые держатся на памяти логистов.

## Предлагаемые решения (дефолты — можно поправить словом)

1. **Где живёт**: отдельная вкладка «⚠ Внештатки» рядом с Диспетчером
   (видна диспетчеру, логисту, продажам, руководителю). Кнопки
   «Акт / Возврат / Опоздание» — в карточке рейса у диспетчера
   (контроль на линии), как просит ТЗ: отметил — рейс продублировался
   во вкладку.
2. **Склады LTL** — живой справочник в «Настройки» (название, адрес,
   телефон, контакт), НЕ зашитый список: адреса из ТЗ станут первичным
   наполнением (Пенза Гагарина/Строителей, Волгоград, Новосибирск,
   Самара, Родники МО, СПб, Екатеринбург). Менять сможет руководитель.
3. **Опоздания** — НЕ руками: факты опозданий на П/В уже считаются из
   отметок (trip_stops, план против факта) — во вкладку они попадают
   автоматически, кнопка «Опоздание» нужна только для случаев без
   отметок. Руками дублировать живой контур нельзя (канон).

## Этапы

### Э1 — фундамент (1 сессия)

- Таблица `trip_incidents`: рейс, тип (act / return / late), кол-во
  паллет/коробок (для возврата), комментарий, кто/когда создал, статус.
- Кнопки «⚠ Акт», «↩ Возврат», «⏰ Опоздание» в карточке рейса
  диспетчера; опоздания сверх допуска подтягиваются автоматом.
- Вкладка «⚠ Внештатки»: три колонки по типам (как просит ТЗ), поиск,
  фильтр по периоду; карточка инцидента со ссылкой на рейс.
- Уведомления: новая внештатка — в «⚙ Конвейер» продажам (акт/возврат
  — их клиент) и руководителю.

### Э2 — возвраты полным циклом (1 сессия)

- Цепочка статусов возврата: «возврат загрузили» → «ждём решения
  клиента» → «отвезти на склад получателя» / «утилизация» /
  «возврат осуществлён» → архив. Два измерения одновременно, как в ТЗ:
  решение (ждём/решено) × местоположение (на борту / склад N) —
  поэтому статус + поле «где лежит» со складом из справочника.
- Справочник складов LTL в Настройках + первичное наполнение из ТЗ.
- Архив с раскрывающимся списком и фильтром (утилизация / возврат
  осуществлён), как просит ТЗ.
- Сторож: возврат «ждём решения» без движения N дней (норматив — из
  факта, кламп) → напоминание продажам с клиентом и сроком.

### Э3 — касания и отчётность (0,5 сессии)

- Сводка руководителю: внештатки недели по типам в «⚡ Сводке периода»
  и утреннем отчёте; возвраты, висящие на складах, с возрастом.
- Карточка клиента: счётчик актов/возвратов за период (аргумент в
  переговорах).
- Вестник: «возвратов закрыто за неделю N» при наличии.
- Аудит сквозных связей по чек-листу CLAUDE.md; гайды «Диспетчер»,
  «Логист», «Продажи».

## Метрики эффекта (правило «мерить каждое улучшение»)

- Возраст открытого возврата до решения клиента (медиана) — должен
  сжиматься.
- Доля возвратов, закрытых без напоминаний.
- Количество актов по клиентам — пища для работы продаж с качеством.

## Не делаем (пока)

- Деньги возвратов (стоимость утилизации, компенсации) — после обкатки
  Э2 отдельным решением.
- Фото-вложения к инциденту — приложатся к Э2, если попросят люди.
