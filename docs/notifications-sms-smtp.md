# Уведомления: Telegram, SMS (smsc.ru), SMTP (reg.ru)

Настройки: **Настройки → Уведомления**.

## SMTP (reg.ru) — проверено

Рабочий хост: **`mail.hosting.reg.ru`**, порт **465**, TLS.
(`smtp.reg.ru` не резолвится — не использовать.)

Логин/From: полный адрес ящика (`info@pegasavto.ru`), пароль — в секрете.

## SMSC.ru — что нужно

| Куда | Поле | Откуда взять |
|------|------|----------------|
| `.secrets/smsc_apikey` | **API-ключ** | [smsc.ru](https://smsc.ru/) → Настройки → Настройки доступа → [Пароли для доступа](https://smsc.ru/passwords/) → создать ключ HTTP/S |
| Настройки → Уведомления | **Логин** | Логин кабинета SMSC (часто телефон или логин регистрации) |
| Настройки → Уведомления | **Имя отправителя** | Зарегистрированное alpha-имя на [smsc.ru/senders/](https://smsc.ru/senders/). Без него уйдёт как `SMSC.RU` |
| — | Баланс | Пополнить счёт в кабинете; кнопка «Баланс SMSC» в настройках |

Достаточно **apikey** (рекомендуется) *или* пары login+пароль; в планере пароль кабинета не храним — только apikey в секрете. Логин в UI полезен, если ключ привязан к аккаунту и API его требует.

IP сервера планера: если в кабинете SMSC включён белый список IP — добавить адрес VPS, иначе ошибка 2.

## Секреты (не в Git)

| Файл | Env | Назначение |
|------|-----|------------|
| `.secrets/smsc_apikey` | `SMSC_APIKEY` / `_FILE` | API-ключ кабинета [smsc.ru](https://smsc.ru/) |
| `.secrets/smtp_password` | `SMTP_PASSWORD` / `_FILE` | Пароль ящика SMTP (reg.ru) |

Логин SMSC, имя отправителя, host/user/from SMTP хранятся в `settings` (БД).
Пароли и apikey из UI не принимаются и не отдаются.

Compose монтирует оба файла как Docker secrets. Пустые файлы допустимы
(канал просто не отправит), но файлы должны существовать на диске.

## Сценарии

Для каждой категории (`stuck`, `daily_report`, …):

- **Уровень** (`notifyRules`): `off` / `critical` / `normal` — кому из
  сотрудников роли уходит внешнее сообщение (как раньше для Telegram).
- **Каналы** (`notifyChannels`): Telegram / SMS / e-mail независимо.
  По умолчанию включён только Telegram.

Лента планера («Конвейер») пишется всегда, независимо от уровня и каналов.

SMS — на `work_phone` / `phone`, почта — на `email` сотрудников роли
(с учётом режима «только аварии» / «все»).

## Поведение вне production

При `NODE_ENV !== production` исходящие Telegram / SMS / SMTP подавлены
(как и раньше для бота), чтобы копия прод-БД на тесте не слала живые сообщения.

## Проверка

На production в разделе «Уведомления»:

1. Сохранить SMTP (host `mail.hosting.reg.ru`, порт `465`, user `info@…`).
2. «Тест письма» на свой ящик.
3. После записи apikey в `.secrets/smsc_apikey` и рестарта — «Баланс SMSC» /
   «Тест SMS».
