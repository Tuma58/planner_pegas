# 08. АРМ — рабочее место каждого сотрудника (план, 07.11.2026)

Предложение руководителя: у каждого сотрудника — рабочее место (АРМ) с
данными для анализа, планирования, выполнения и постановки задач; все
места однотипные по навигации и дизайну.

Статус: **утверждён 07.11**; **Э1–Э5 готовы** — АРМ у всех должностей, включая водителя.

## 1. Что уже есть в планере (берём лучшее, не дублируем)

| Что | Где | Кому сейчас | В АРМ станет |
|---|---|---|---|
| «◉ Моё поле»: коэффициент, потери, стыки, очереди, задачи отдела, люди, деньги, KPI | field.js / fieldData | руководители отделов | АРМ руководителя — тот же каркас |
| «🏅 Моя смена»: операции по имени за смену, сравнение с медианой | myShiftStats | диспетчеры, логисты, планирование | зона «Анализ» исполнителя |
| Задачи смены с отметкой «сделано» | task_marks (sales / logist / dispatcher), боковая панель | три группы Логистики | зона «Задачи», раздел «по процессу» |
| Задачи Ресурса | renderResourceTasks | эксплуатация | зона «Задачи» |
| Очереди «сейчас» с переходом в экран | fieldLive.queues | руководители | зона «Выполнение» — очереди своей работы |
| Сигналы на стыках «⚑ / ✓» | joint_signals | руководители и контролёры стыков | зона «Задачи», раздел «от соседнего отдела» |
| KPI паспорта должности с привязкой к живым цифрам | kpiBinding, structure | руководители | зона «Анализ», у каждого — свой паспорт |
| Цели и задачи отделов | org_goals | Штаб, руководители | шапка АРМ: «моя задача отдела» |
| HELP DESK заявки | helpdesk_tickets | все | зона «Задачи», раздел «мои заявки» |
| Рабочие экраны (Логист, Диспетчер, Ресурс, Ремзона, Склад…) | меню | по наборам ролей | не меняются, АРМ ведёт в них «→» |

**Вывод:** почти все данные уже есть, но разбросаны по пяти местам и
у каждой группы выглядят по-своему. АРМ их **собирает в один экран**, а
новых расчётов почти не требует. Единственное новое — **постановка задач
человеку** (сейчас поставить задачу конкретному сотруднику с
сроком и отчётом негде, только сообщение в чате).

## 2. Каркас — один для всех

```
┌ Шапка ─────────────────────────────────────────────────────────────┐
│ ФИО · должность · отдел · смена сейчас      мой KPI-индекс  [период]│
│ Задача отдела, в которую я вношу вклад (из «Целей и задач»)         │
├ 1. АНАЛИЗ ──────────────────┬ 2. ПЛАН ─────────────────────────────┤
│ мои показатели против нормы │ что на мне сегодня / завтра /       │
│ (KPI паспорта должности),   │ горизонт плана: рейсы, заявки,      │
│ тренд по неделям, где теряю │ выпуски, наряды, приходы — по роли  │
├ 3. ВЫПОЛНЕНИЕ ──────────────┼ 4. ЗАДАЧИ ───────────────────────────┤
│ мои очереди СЕЙЧАС: число,  │ поставленные мне (срок, от кого),   │
│ самый старый случай, → в    │ по процессу (task_marks), сигналы   │
│ рабочий экран               │ стыков, мои заявки HELP DESK;       │
│                             │ руководителю — «＋ Поставить задачу»│
└─────────────────────────────┴──────────────────────────────────────┘
```

Правила одинаковости:
- **один экран «Моё рабочее место»** — первый пункт меню у всех и
  стартовый экран при входе; заменяет «Моё поле», «Мою смену» и боковые
  панели задач (их данные переезжают в зоны);
- **четыре зоны всегда в одном порядке и на одном месте**; пустая зона не
  исчезает, а пишет «нет данных — источник такой-то»;
- **одни и те же элементы BI-кита**: плитка показателя (значение / норма /
  цвет), строка очереди (число · старейший · «→»), карточка задачи (срок,
  от кого, статус);
- **цвет отдела** в шапке (как в меню), больше никаких отличий;
- содержимое задаётся **реестром виджетов по должности** (как реестр
  отчётов): добавить должности данные — строка в реестре, не новый экран.

## 3. Постановка задач (новое)

Таблица `arm_tasks`: кто поставил, кому (сотрудник или должность),
что сделать, срок, связанный объект (рейс, машина, клиент, наряд — по
желанию), статус (новая → в работе → сделано / не сделано с причиной),
результат.

- **Кто ставит:** руководитель — своим подчинённым по структуре
  (руководитель направления — всем, руководитель отдела — своему отделу,
  начальник автоколонны — водителям своей колонны через Telegram).
- **Уведомление** — в личную ленту и Telegram, как адресные сообщения
  конвейера.
- **Просрочка** видна у исполнителя и у поставившего; процент задач в
  срок — показатель в зоне «Анализ» (живой, без зашитых норм).
- **Руководитель видит АРМ подчинённого** («глазами сотрудника») — тот
  же экран, только чтение.
- Между отделами задачи **не ставятся** — для этого стыки и «⚑ Сигнал».

## 4. Наполнение по должностям (реестр виджетов)

| Должность | Анализ | План | Выполнение | Задачи по процессу |
|---|---|---|---|---|
| Руководитель направления | каскад КТГ→КВЛ→КИП→КЭИП, выручка против плана | план месяца, портфель заявок | очереди всех отделов (свод) | сигналы стыков, задачи отделам |
| Руководитель логистики | КИП, выручка и маржа на МД, бдительность стыков | заявки на завтра против свободных машин | заявки без ТС, свободные без задания, опоздания | стык Эксплуатация→Логистика |
| Специалист планирования | моя смена: заявки, согласования; CRM-воронка | заявки клиентов на горизонт | заявки без ответа, согласование | задачи продаж (task_marks sales) |
| Логист-диспетчер | моя смена: назначения, качество подбора | машины под выгрузку без следующего | заявки без ТС, брони | задачи логиста |
| Диспетчер-контролёр | опоздания П/В, сверка сумм | рейсы в пути, точки сегодня | рейсы позже срока, наличные | задачи диспетчера |
| Руководитель эксплуатации | КВЛ, текучесть, ФОТ водителей | водители на завтра, пересменки | без водителя, на пересменке, на стоянке | стык ТОиР→Эксплуатация |

| Водитель | Mini App «Мой рейс» — те же 4 зоны в Telegram (этап 5) | | | |

У каждой строки источник — существующая функция (fieldLive,
myShiftStats, kpiDept, toStatusAll, partsStock, safetyBoard,
releaseBoard, docsBoard…). Новых формул нет.

## 5. Этапы

| Этап | Что | Готово, когда |
|---|---|---|
| **Э1** | Каркас АРМ + реестр виджетов + 4 пилотные должности: логист-диспетчер, диспетчер-контролёр, диспетчер учёта, механик | 4 роли работают в АРМ, старые панели у них не нужны |
| **Э2** | Постановка задач `arm_tasks` + «глазами сотрудника» у руководителя | руководитель ставит задачу, видит выполнение и просрочку |
| **Э3** | Остальные должности по таблице | у всех 16 наборов — АРМ стартовым экраном |
| **Э4** | «Моё поле» руководителей переезжает в каркас АРМ; «Моя смена» и боковые панели задач — убрать по счётчику использования | одно место вместо трёх |
| **Э5** | АРМ водителя в Telegram Mini App тем же каркасом; личный KPI-индекс → ФОТ | |

Каждый этап — в лаборатории, с тестами, справкой и проверкой под
ролями; перенос в планер — по вашему слову.
