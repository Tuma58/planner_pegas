# Проект «Слияние» · Блок 4 — «KPI и каскад»

Статус: **план до утверждения** (07.11.2026). Кода нет. Сверка: main не
менялся с путевых листов (влиты 96207d4). Рамка — «Поле управления»: у
каждого из четырёх руководителей своя панель, у Штаба общая; каждый
процесс связан в коде.

## 1. Что такое «KPI и каскад» в среде СТ

1. **Каскад и владение:** КТГ 97% (ТОиР) → КВЛ 99% (Эксплуатация) →
   КИП 99% (Логистика) → КЭИП 95% (свод).
2. **Формулы каскада** — в планере совпадают с каноном main 6f2c390.
3. **Два KPI на отдел:**
   - основной — машино-дни своего этапа;
   - второй — ЦФО на машино-день.
4. **Сквозной контроль «мерим бдительность»** — 20–30% KPI. Отдел
   премируется за скорость и полноту сигнала соседу, а не за чужую цифру:
   - ТОиР контролирует КВЛ: ТС из ремонта без водителя;
   - Эксплуатация контролирует КИП: укомплектованные без задания;
   - Логистика контролирует КТГ: окна ТО без просрочки пробега.
5. **Упреждающий контроль.** Ловить опережающий сигнал до того, как
   коэффициент просядет. У каждого коэффициента свои сигналы и действия
   (таблица в 3.3).
6. **KPI в паспортах должностей** — 2–4 показателя с нормой у каждой из 24
   должностей. Пример, Логист-диспетчер: «доля назначений в норматив
   ≥95%», «рейсы без ошибок в учётной системе ≥99%», «задержки с
   причиной 100%».

В среде всё это — **текст**. Ни одна цифра не живая, сигналы никто не
подаёт.

## 2. Что уже работает в планере — берём как есть

| Нужно по среде | Уже есть в планере |
|---|---|
| Каскад и формулы | `parkReportData` — канон среды СТ (main 6f2c390); цели — реестр целей (блок 2) |
| Основной KPI — машино-дни этапа | разбивка машино-дней сводного снимка; поля отделов (Э1/Э2) |
| Второй KPI — ЦФО на МД | ₽ на машино-день (блок 3) |
| Задание до выгрузки (опережающий сигнал КИП) | `tripsWithoutNext` — сигнал «следующий рейс не назначен» за 2 ч до выгрузки; `nextAssignedShare` |
| Зазор стыковки | `gapStats` |
| KPI диспетчеров и логистов | «Показатели сотрудников» (`staffReport`), «Моя смена» (`myShiftStats`, норма должности), выученная ёмкость диспетчера, «Герой недели» |
| KPI водителей | `driverPeriodMetrics`, личный КИП водителя, сверхвахта |
| Время по стыкам конвейера | проект «160 млн» (`HANDOFFS`: подтверждение, назначение, 1С, задание, линия) |

**Зазор:** сквозного контроля как процесса нет. Стыки в поле (Э1) сейчас
показывают, что висит, но никто не подаёт и не принимает сигнал. Значит,
бдительность не измерить. KPI паспортов не связаны с живыми цифрами.

## 3. Что делаем

### 3.1. Панель «◎ KPI и каскад» — Штаб и срез отдела

- **Каскад и владение вживую.** У каждого коэффициента: значение за
  период, цель, ход по дням и неделям, владелец — должность и человек.
- **Два KPI отдела.** Машино-дни этапа (потери против цели) и ЦФО на
  машино-день.
- **Сквозной контроль** — бдительность контролёра и скорость устранения
  у владельца (из 3.2).
- **Опережающие сигналы сейчас** — из 3.3.
- **KPI должностей отдела** — из 3.4.
- **Кто видит.** Штаб видит все отделы. Руководитель отдела видит свой
  отдел в блоке отдела. В «Моём поле» появляется секция «Мои KPI».

### 3.2. Сквозной контроль — процесс в коде («сигнал на стыке»)

Новый журнал `joint_signals`. Одна запись — один случай на стыке:
`joint · машина · условие возникло (время) · сигнал подан (кто, когда) ·
принят владельцем (кто, когда) · устранено (когда, чем)`.

1. **Система сама видит условие** — то же, что в поле (Э1):
   - машина вышла из ремонта и стоит без водителя;
   - укомплектованная машина без задания.

   Случай открывается автоматически, время возникновения пишется.
2. **Контролёр подаёт сигнал** одной кнопкой в своём поле: «⚑ Сигнал»
   у машины на стыке.
   - Ремзона — по «из ремонта без водителя».
   - Эксплуатация — по «без задания».
3. **Сигнал уходит:**
   - уведомлением роли-владельцу в чате: `resource` для Эксплуатации,
     `logist`/`sales` для Логистики — коды прав не меняются;
   - карточкой во «входящие» поля отдела-владельца.
4. **Владелец принимает** («✓ Принято») и устраняет.
5. **Случай закрывается сам по факту:**
   - назначен водитель — диспозиция «без водителя» снята или подрезана
     выездом (механизм main);
   - назначен рейс.

**KPI из журнала:**
- **у контролёра** — доля случаев с сигналом вовремя и медиана «условие →
  сигнал»;
- **у владельца** — медиана «сигнал → устранено».

Норма «вовремя» — **живая**: медиана факта за 28 дней в коридоре
здравого смысла, фолбэк — до накопления фактов. Цель задаёт руководитель
в Настройках. Дрейф — строкой в «📐 Нормативах недели».

**Логистика → ТОиР** («окна ТО без просрочки») — тот же журнал, но
условие появится с интервалами ТО (блок «Процессы и контроль»).

### 3.3. Опережающие сигналы — на каждом поле, на «сейчас» и «завтра»

| Коэффициент | Сигнал (из данных планера) | Действие (куда ведёт) |
|---|---|---|
| КТГ · ТОиР | заезды без даты выпуска; просроченный плановый выпуск; рост медианы срока ремонта к прошлым 4 неделям | Ремзона |
| КВЛ · Эксплуатация | исправные ТС **без водителя на завтра**; ТС из ремонта сегодня без экипажа | Ресурс → закрепление |
| КИП · Логистика | ТС **без следующего задания к выгрузке** (`tripsWithoutNext`); портфель заявок на завтра меньше свободных ТС; клиенты с историей простоя в завтрашнем плане | Логист / Планирование |
| КЭИП · Штаб | дневной светофор трёх коэффициентов против цели; прогноз месяца по темпу недели против плана (прогноз дашборда) | поле направления |

Сигналы не дублируют уведомления чата, которые уже работают. Они
собирают их в одно место — поле владельца.

### 3.4. KPI должностей — паспорт → живой показатель

- **Строка KPI паспорта получает ключ** каталога показателей (блок 2) или
  личного показателя. Разметка — разовая, по таблице; дальше её правят
  в карточке должности.
- **Измеримо уже сейчас:**
  - **руководители отделов** — основной (машино-дни), второй (ЦФО/МД),
    сквозной (из 3.2);
  - **логист-диспетчер** — «Показатели сотрудников»: назначения в
    норматив, ошибки 1С, задержки с причиной;
  - **диспетчер-контролёр** — слоты, реакция на инцидент, холодовая цепь,
    из доски;
  - **водитель** — слот, нарушения, топливо по РН-Карт;
  - **ТОиР** — выпуск в срок, повторные ремонты, из Ремзоны.
- **Неизмеримое** (охрана, кладовщик, мастер цеха…) остаётся с пометкой
  «оценка руководителя». Ручная отметка за месяц — в блоке «ФОТ»: там
  KPI превращаются в деньги.
- **Вес «свой KPI / контроль соседа»** — настройка по отделу. По
  умолчанию 75/25, в коридоре среды 70–80 / 20–30.

### 3.5. Роли — кто видит и кто делает

| Роль | Видит | Делает |
|---|---|---|
| Руководитель направления | панель KPI всех отделов, свод бдительности | задаёт цели и веса |
| Руководитель логистики | KPI Логистики, входящие сигналы «без задания» | принимает сигнал, ставит задание; подаёт сигнал «окна ТО» (позже) |
| Главный механик | KPI ТОиР | подаёт сигнал «из ремонта без водителя» |
| Руководитель эксплуатации | KPI Эксплуатации, входящие «из ремонта без водителя» | принимает и закрепляет водителя; подаёт сигнал «без задания» |
| Начальник автоколонны, диспетчер учёта | — | принимают сигнал «из ремонта без водителя» в Ресурсе (уведомление роли `resource`), закрепляют водителя |
| Механик / старший смены | — | может подать сигнал из Ремзоны при выпуске |
| Логист, планирование | свой KPI в «Моей смене» | принимают сигнал «без задания» в Логисте / Планировании |

## 4. Касания

- **Новое:**
  - `joint_signals` с детектором условий — тик раз в 5 минут, как у
    сторожей;
  - ключи KPI у строк паспорта;
  - панель KPI;
  - секции «Мои KPI» и «Входящие сигналы» в поле.
- **Меняется:**
  - `field.mjs` — стыки с кнопками;
  - уведомления сигналов через существующий `notify(роль)`;
  - «Нормативы недели» — строка бдительности.
- **Не трогаем:** формулы каскада (канон main), «Показатели сотрудников»,
  «Мою смену», «160 млн» — читаем их.
- **Тесты:**
  - детектор открывает и сам закрывает случай;
  - сигнал и принятие с правами по роли;
  - KPI бдительности;
  - срез панели по области.
