# Проект «Слияние» · Блок 1 — «Обзор структуры»

Статус: **план до утверждения** (05.11.2026). Кода нет.
Порядок блоков — по навигатору «Рабочей среды СТ»: Обзор структуры →
Цели и задачи → ЦФО и затраты → KPI и каскад → Процессы и контроль →
Система отчётов → P&L → Машино-дни → ФОТ → Масштабирование →
Укомплектованность → Табель аппарата → Паспорта → Документы.

## 1. Что такое «Обзор структуры» в среде СТ

- 4 блока = 4 отдела, у каждого свой коэффициент каскада:
  Штаб — КЭИП (сквозной), Логистика — КИП (99% от КВЛ),
  Эксплуатация — КВЛ (99% от КТГ), ТОиР — КТГ (97% от списка).
- 24 должности со штатной численностью (всего 250 человек):
  - **Штаб, 8:** руководитель направления 1, специалист по БДД 2, АХО 1,
    охранник-парковщик 4.
  - **Логистика, 14:** руководитель отдела 1, группа планирования и
    анализа 2, логист-диспетчер 3, **диспетчер-контролёр группы
    контроля 8**.
  - **Эксплуатация, 7 + 195 водителей:** руководитель отдела 1 (новая),
    начальник автоколонны 2, диспетчер учёта 2 (новая), контролёр
    техсостояния 2 (приём-передача ТС), водитель-экспедитор 195.
  - **ТОиР, 26:** главный механик 1, старший смены 2, дежурный механик 2,
    оператор 2, мастер цеха 2, слесарь-диагност 2, слесарь 10, закупка
    запчастей 1, кладовщик 2, снабженец 1, закупка/продажа ТС 1.
- Сверху плитки: 128 ТС · 195 водителей · 55 штат аппарата · 95% цель.
- Клик по должности открывает её паспорт: общие положения,
  квалификация, функции, обязанности, права, взаимодействие,
  ответственность, KPI, у водителя ещё положение об оплате.
- Данные живут в localStorage браузера; есть «Экспорт всего» в JSON.

## 2. Что есть в планере и как оно соотносится

| Структура СТ | Планер сейчас | Зазор |
|---|---|---|
| Должность (24, справочник) | `users.job_role` — свободный текст | нет справочника, нет штата |
| Роль = права доступа | `users.roles` (8 ролей) | роли ≠ должности — это верно, но связи нет |
| Водитель-экспедитор 195 | таблица `drivers` (статусы, закрепление) | штат против факта не сравнивается |
| Отдел и его коэффициент | навигатор по отделам (наш BI-вид), каскад в `parkReportData` | коэффициенты в шапке без живых значений |
| Паспорт должности | нет | только в файле среды |
| Укомплектованность | «Сотрудники» (список), явка водителей | нет «штат / факт / вакансии» |

На должность в планере опираются уже работающие контуры, их нельзя
сломать:
- **«Показатели сотрудников» и норма должности** (planner-service:
  `jobRoles`, база должности за 7 суток, `roleKey = job_role || role`) —
  нормативы сравниваются по тексту должности.
- **Эскалации доски** — `esc_role` (senior/head), перенесён с текста
  должности 21.10; `dispatch_exempt` — исключение из автораспределения.
- **Телефония** — карточка звонка показывает `job_role`.
- **Карточка сотрудника и табель смен офиса** (staff.mjs).

**Расхождение навигатора со структурой.** Экран «Диспетчер» (доска
сопровождения рейсов, контроль слотов, холодовая цепь, инциденты) — это
работа **группы контроля отдела Логистики**, а у нас он стоит в
Эксплуатации. Эксплуатации по структуре принадлежат выпуск на линию,
водители и закрепление (Ресурс), табель и пересмены, приём-передача ТС.
**Отдела продаж в структуре СТ нет** — нужно решение (вопрос 1).

## 3. Что предлагаю сделать в блоке 1

**1.1. Справочник структуры в планере.**
- Новая таблица должностей: отдел, номер, название, штат, статус,
  паспорт.
- Наполняется импортом JSON из «Экспорт всего» файла среды. Повторный
  импорт показывает разницу (что добавилось, изменилось, исчезло) и
  применяет её по подтверждению. Версия импорта пишется в журнал.
- Штат — цель из структуры, не константа в коде.
- Касания: только новая таблица и Настройки → раздел «Структура».

**1.2. Привязка сотрудника к должности.**
- В карточке сотрудника — выбор должности из справочника, рядом с
  ролью: роль = права, должность = место в структуре.
- Разовая подсказка-миграция: текст `job_role` → должность
  справочника по совпадению. Несопоставленные — списком на ручную
  привязку, автоматически ничего не переписываем.
- **`job_role` сохраняется как есть**, чтобы не сломать нормативы
  «Показателей сотрудников», телефонию и эскалации. Перевод нормативов
  на должность справочника — отдельным шагом в блоке «KPI и каскад».
- Водители относятся к должности «Водитель-экспедитор» автоматически,
  из таблицы `drivers`.

**1.3. Экран «Структура» — первый в навигаторе, Штаб.**
- **Плитки (план против факта):**
  - ТС в списке — 127 из 128;
  - водители — активные из 195;
  - аппарат — привязанные сотрудники из 55;
  - использование парка — факт против 95%.
- **Четыре колонки-отдела**, как в среде. У отдела — коэффициент
  **с живым значением** из канона `parkReportData` (сейчас в шапке только
  подписи). У каждой должности: штат / факт / вакансии, клик — люди на
  должности и паспорт для чтения.
- **Касания — только чтение:** справочник, users, drivers, vehicles,
  `parkReportData`. Ни одна запись не меняется.

**1.4. Навигатор по структуре.**
- Экраны перегруппировать по отделам и группам структуры:
  - **Логистика:** планирование (Конструктор, План вывоза, Потоки),
    назначение (Логист, Гант), контроль (Диспетчер, Мониторинг,
    Внештатки);
  - **Эксплуатация:** Ресурс, План парка;
  - **ТОиР:** Ремзона;
  - **Штаб:** Структура, Дашборд, Руководитель, Сотрудники, Затраты.
- Подсветка «мой отдел» — по должности сотрудника, а не по роли.
- Касания: только `NAV_GROUPS` и привязка отдела в app.js. Права и
  экраны не меняются.

**Чего в блоке 1 НЕ делаем** (это следующие блоки):
- KPI и премии по должностям;
- ФОТ;
- табель аппарата;
- редактирование паспортов в планере — пока источник паспортов файл
  среды, в планере только чтение.

## 4. Как мерим эффект

- **Укомплектованность по отделам:** «штат / факт» видна впервые.
- **Доля сотрудников, привязанных к должности справочника:** цель 100%.
  Отчёт о дрейфе — в «Нормативах недели».

## 5. Вопросы руководителю

1. **Продажи.** В структуре СТ отдела продаж нет. Куда относим экран
   «Продажи» и сотрудников продаж?
   - (а) в Логистику: функция руководителя отдела — «взаимодействие с
     заказчиком»;
   - (б) отдельная коммерческая служба вне штата СТ — в обзоре «вне
     структуры»;
   - (в) группа планирования и анализа.
2. **Источник истины структуры.** Предлагаю: файл среды — место, где
   структуру проектируют; планер её импортирует и считает факт.
   Правка структуры остаётся в файле среды, в планере — только импорт.
   Или переносим редактор в планер?
3. **Перенос «Диспетчера» в Логистику** (группа контроля) — подтвердить.
4. **Факт укомплектованности.** В лабораторной копии базы сотрудников нет.
   Для проверки на реальных людях нужен доступ на чтение к прод-базе или
   выгрузка сотрудников (ФИО, должность, роль).
